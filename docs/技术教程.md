# 从零搭建「抖音收藏知识库」

面向技术人员。读完你能自己实现一套：把收藏夹里的视频，变成可全文检索的知识库。

全部代码在本仓库，可直接跑。本文重点讲**为什么这么设计**，以及那些踩过的坑。

---

## 一、问题定义

收藏了 700 条抖音视频，但：

1. **搜不到** — 抖音收藏夹只能按标题搜，而标题往往是「9021 Codex太强了…」这种，真正的干货在语音里
2. **想不起** — 遇到问题时压根想不起自己收藏过相关内容
3. **分类无效** — 按话题分（AI/生活/教育），400 条全挤在「AI」里，等于没分

目标：**遇到问题时，30 秒内找到「别人是怎么解决的」**。

技术上拆成四步：抓列表 → 拿音频 → 转文字 → 建索引。

---

## 二、技术选型

| 环节 | 选择 | 原因 |
|---|---|---|
| 抓取 | Playwright + 真实 Chrome（CDP） | 抖音风控强，纯 HTTP 请求签名难破 |
| 下载 | yt-dlp | 抖音 CDN 地址有时效签名，yt-dlp 已处理好 |
| 转写 | faster-whisper (small, int8) | 本地跑、免费、中文够用；M 系列芯片约 3-5x 实时 |
| 分类 | 规则 + 权重打分 | 可解释、可调；LLM 分类贵且不稳定 |
| 输出 | 单文件 HTML | 双击即用，无需服务器 |

**为什么不用 LLM 分类？** 700 条调 API 要钱，且同样输入可能给出不同分类。规则引擎虽然要手工写词表，但完全可控——发现归错了，改一行词表重跑，几秒钟。

## 三、第一步：抓取收藏列表

### 3.1 为什么必须用真实浏览器

抖音的 `/aweme/v1/web/...` 接口需要 `X-Bogus`、`a_bogus` 等签名参数，由前端 JS 生成，逆向成本高且经常变。

绕过办法：**用真实浏览器加载页面，监听它自己发出的 XHR 响应**。

```python
# 抓取和转写两个步骤都用 Playwright 自动拉起同一个 Chrome（同一个资料夹），
# 不再需要手动启动浏览器或固定调试端口
ctx = p.chromium.launch_persistent_context(
    user_data_dir=os.path.expanduser("~/.codex-douyin-profile"),
    channel="chrome", headless=False,
    ignore_default_args=["--enable-automation"])
```

用独立 `user-data-dir` 的好处：不干扰日常 Chrome，登录态还能长期保留；
转写步骤复用同一个资料夹，因此第 1 步登录一次，第 2 步直接复用登录态导出 cookie。

### 3.2 双通道抓取

```python
# 通道 1：监听接口响应（数据全，有 tags/author 等字段）
def on_response(resp):
    if "aweme/v1" not in resp.url:
        return
    if "json" not in resp.headers.get("content-type", ""):
        return
    data = resp.json()
    tmp = []
    extract_item(data, tmp)          # 递归找 aweme_id 结构
    for it in tmp:
        rec = api_to_record(it)
        if rec and rec["id"]:
            api_items.append(rec)

page.on("response", on_response)

# 通道 2：DOM 兜底（接口漏了的从页面元素捞）
rows = page.evaluate(EXTRACT_JS)     # querySelector 抓 a[href*="/video/"]
```

**为什么要两个通道？** 接口偶尔会因为翻页机制漏数据；DOM 里能看到的一定不会漏。两边取并集，用 `id` 去重。

### 3.3 滚动的坑

抖音收藏列表是**内嵌滚动容器**，不是 `window` 滚动。直接 `window.scrollTo` 没用。

```javascript
// 找出真正在滚的那个容器：scrollHeight 明显大于 clientHeight
const cands = [...document.querySelectorAll('div')].filter(el => {
  const s = getComputedStyle(el);
  return /(auto|scroll)/.test(s.overflowY)
      && el.scrollHeight > el.clientHeight + 200;
});
// 选面积最大的那个
```

还要配合鼠标滚轮事件，有些懒加载只认真实滚轮：

```python
b = page.locator('a[href*="/video/"]').first.bounding_box()
page.mouse.move(b["x"] + b["width"]/2, b["y"] + b["height"]/2)
page.mouse.wheel(0, 900)
```

### 3.4 增量抓取

全量抓 700 条要十几分钟。日常只新增几条，没必要每次全抓。

思路很简单：**连续遇到 N 条已知 ID 就停**。

```python
if rec["id"] not in seen:
    seen.add(rec["id"]); total_new += 1
    known_streak = 0                      # 遇到新的，计数清零
    fj.write(json.dumps(rec, ensure_ascii=False) + "\n")
elif args.incremental:
    known_streak += 1                     # 遇到旧的，累加

if args.incremental and known_streak >= args.stop_after_known:
    log("连续 %d 条均为旧视频，新内容已抓完" % known_streak)
    break
```

阈值设 40，因为收藏列表按时间倒序，新收藏都在最前面。留 40 条缓冲避免误停。

**边写边存**：每条抓到就 append 进 `jsonl`，Ctrl+C 不丢数据，下次自动续抓。

## 四、第二步：下载音频

### 4.1 Cookie 传递

yt-dlp 需要登录态。从 Playwright 导出成 Netscape 格式：

```python
def write_cookies(ctx):
    lines = ["# Netscape HTTP Cookie File"]
    for c in ctx.cookies():
        dom = c.get("domain", "")
        if "douyin" not in dom and "amemv" not in dom:
            continue
        inc = "TRUE" if dom.startswith(".") else "FALSE"
        secure = "TRUE" if c.get("secure") else "FALSE"
        exp = int(c.get("expires") or 0)
        lines.append(f"{dom}\t{inc}\t{c.get('path','/')}\t{secure}\t{exp}\t{c['name']}\t{c['value']}")
    COOKIE_FILE.write_text("\n".join(lines) + "\n", encoding="utf-8")
```

然后：

```python
cmd = [YDL, "--cookies", COOKIE_FILE,
       "-f", "bestaudio/best", "-x", "--audio-format", "mp3",
       "-o", f"{AUDIO_DIR}/{vid}.%(ext)s", url]
```

只要音频（`-x`），体积比视频小一个数量级。

### 4.2 坑：误导性报错

有些视频下载失败，yt-dlp 报：

```
ERROR: [Douyin] xxx: Fresh cookies (not necessarily logged in) are needed
```

字面意思是 Cookie 过期。但重新导出 Cookie、甚至用浏览器打开该视频页再导，都没用。

**真实原因**：作品已被作者删除或设为私密。直接查详情接口就清楚了：

```python
def aweme_detail(vid):
    qs = urllib.parse.urlencode({"aweme_id": vid, "aid": "6383", ...})
    req = urllib.request.Request(
        "https://www.douyin.com/aweme/v1/web/aweme/detail/?" + qs,
        headers={"User-Agent": UA, "Referer": "https://www.douyin.com/",
                 "Cookie": "; ".join(f"{k}={v}" for k, v in _cookies().items())})
    data = json.loads(urllib.request.urlopen(req, timeout=20).read())
    ad = data.get("aweme_detail")
    if ad:
        return ad, None
    fd = data.get("filter_detail") or {}
    return None, fd.get("detail_msg") or "作品不可获取"
```

返回的是：`因作品权限或已被删除，无法观看`。

看 yt-dlp 源码能确认这是它的通用兜底提示：

```python
# yt_dlp/extractor/tiktok.py
if not detail:
    # TODO: Run verification challenge code to generate signature cookies
    raise ExtractorError('Fresh cookies (not necessarily logged in) are needed', ...)
```

**教训**：第三方库的错误信息只是它的猜测，别照单全收。直接问数据源。

### 4.3 预检查省时间

这个接口顺带能拿到时长，于是把「失效判定」和「超长过滤」合并成一次调用，放在**下载之前**：

```python
if not (AUDIO_DIR / f"{vid}.mp3").exists():
    detail, err = aweme_detail(vid)
    if err:                                    # 失效 → 记录后永久跳过
        state["dead"][vid] = {"reason": err, ...}
        save_state(state); continue
    mins = video_minutes(detail)               # duration 字段单位是毫秒
    if args.max_minutes and mins and mins > args.max_minutes:
        state["too_long"][vid] = {"minutes": mins, ...}
        save_state(state); continue
```

实测收益：有条 3 小时 48 分的视频，下载 411MB + 转写花了 1 小时以上。预检查后直接跳过。

### 4.4 状态库

`data/state.json` 记录 `dead` 和 `too_long`，避免重复劳动：

```json
{
  "dead": {
    "7402670121279442215": {
      "reason": "因作品权限或已被删除，无法观看",
      "title": "帕加尼Utopia制造工厂探秘（第2集）",
      "at": "2026-09-11T14:32:10"
    }
  },
  "too_long": {
    "7120206469609393415": { "minutes": 229.0, "title": "一口气看完《走向共和》" }
  }
}
```

## 五、第三步：语音转文字

### 5.1 模型选择

`faster-whisper` 的 `small` 模型 + int8 量化，CPU 上跑：

```python
model = WhisperModel(model_path, device="cpu", compute_type="int8")
segments, info = model.transcribe(str(mp3), language="zh", vad_filter=True)
```

- `language="zh"` — 指定中文，跳过语种检测，更快更准
- `vad_filter=True` — 语音活动检测，自动跳过静音段，纯 BGM 的视频会输出空文本（正好用来识别「无人声」）

实测 700 条（平均 3-5 分钟）在 M 系列芯片上跑了约 18 小时。追求速度可换 `tiny`，追求精度换 `medium`。

### 5.2 坑：HuggingFace 镜像下载失败

`WhisperModel("small")` 会自动从 HuggingFace 下载。国内需要走镜像：

```python
os.environ.setdefault("HF_ENDPOINT", "https://hf-mirror.com")
```

但仍然失败：

```
FileMetadataError: Distant resource does not seem to be on huggingface.co.
LocalEntryNotFoundError: An error happened while trying to locate the file on the Hub
```

排查过程：
1. `curl` 镜像 API — 通的，返回正常 JSON
2. `curl -I` 各个文件 — 小文件都带 `x-repo-commit` 头，**但 `model.bin` 重定向到了 `cas-bridge.xethub.hf.co`**
3. 看 `huggingface_hub` 源码：

```python
# file_download.py
commit_hash = metadata.commit_hash
if commit_hash is None:
    raise FileMetadataError("Distant resource does not seem to be on huggingface.co...")
```

新版 `huggingface_hub` (1.8.0) 走 Xet 存储协议，镜像的重定向链上丢了 `X-Repo-Commit` 头。

**解决**：绕开 hub 库，直接 curl 下载到本地目录，然后传路径而非模型名：

```bash
BASE="https://hf-mirror.com/Systran/faster-whisper-small/resolve/main"
for f in config.json tokenizer.json vocabulary.txt; do
  curl -sL --retry 3 -o "$MODEL_DIR/$f" "$BASE/$f"
done
curl -L --retry 3 -C - -o "$MODEL_DIR/model.bin" "$BASE/model.bin"
```

```python
local_model = PIPE_DIR / "models" / f"faster-whisper-{args.model}"
model_src = str(local_model) if local_model.is_dir() else args.model
model = WhisperModel(model_src, device="cpu", compute_type="int8")
```

`-C -` 支持断点续传，460MB 断了能接着下。

### 5.3 断点续跑

每条转完立刻写独立 JSON：

```python
out = TRANS_DIR / f"{vid}.json"
out.write_text(json.dumps(rec, ensure_ascii=False, indent=2), encoding="utf-8")
```

主循环开头检查文件是否存在，存在就跳过。18 小时的任务中断了也不怕。

**为什么一条一个文件？** 单个大 JSON 每次写要全量序列化，且中断可能损坏。独立文件天然隔离。

## 六、第四步：分类体系（最关键）

### 6.1 为什么按话题分是错的

第一版按话题分类：AI 与智能 400、教育与成长 79、生活与健康 50……

**400 条挤在一个类里，跟没分类一样。**

根因：**收藏的本质是「解决方案库」，不是「学科资料库」**。你收藏 Codex 教程不是为了研究 AI，是为了将来写代码时能用上。

### 6.2 需求导向的三级结构

改成按「我遇到什么问题会来翻它」组织：

```
一级 = 我要解决什么问题     AI 编程与智能体
二级 = 具体场景             能力扩展
三级 = 具体方案/工具        Skills 技能 / MCP 工具接入 / 子代理
```

想给 AI 加能力 → `AI 编程与智能体 › 能力扩展 › Skills 技能`，一步到位。

### 6.3 权重打分

```python
TAXONOMY = [
    ("AI 编程与智能体", "编程 Agent", "Claude Code",
     [("claude code", W_STRONG), ("claudecode", W_STRONG), ("claude", W_MED)]),
    ...
]

def classify(title, tags, transcript, min_score=6):
    head = _norm(f"{title} {tags}")     # 标题+话题
    body = _norm(transcript)            # 转写全文
    best_score, best_path = 0, None
    for l1, l2, l3, kws in TAXONOMY:
        s_head = s_body = 0
        for kw, w in kws:
            hc = _count(head, kw)
            if hc:
                s_head += w * 10 * min(hc, 2)    # 标题权重 ×10
            bc = _count(body, kw)
            if bc:
                s_body += w * min(bc, 3)         # 正文权重 ×1
        total = s_head + s_body
        if total > best_score:
            best_score, best_path = total, [l1, l2, l3]
    if not best_path or best_score < min_score:
        return ["其他", "未归类", "待整理"], best_score, "none"
    return best_path, best_score, best_src
```

两个设计点：

- **标题权重 ×10**：标题是作者的主动概括，比正文里顺口提一句可靠得多
- **命中次数封顶**（`min(hc,2)` / `min(bc,3)`）：防止一个词刷屏就压倒其他信号

效果：把转写全文纳入后，**32 条从「其他」被救回**，未归类从 43 降到 12。

### 6.4 坑：英文子串误匹配

`"skill" in text` 会命中 `skillful`、`skilled`。实际发生过：一条「Java远程职位」的视频被打上 `Skills` 标签。

```python
_ASCII = re.compile(r"^[a-z0-9 .+#/-]+$")

def _count(hay, needle):
    """英文按词边界计数，中文直接子串计数。"""
    if _ASCII.match(needle):
        return len(re.findall(r"(?<![a-z0-9])" + re.escape(needle) + r"(?![a-z0-9])", hay))
    return hay.count(needle)
```

中文不能用 `\b`（中文之间没有词边界），所以要按语言分流处理。

### 6.5 术语抽取：词典 > 词频

第一版用词频抽关键词，结果全是「大家、今天、其实、可以」这种噪音。

改成**术语词典匹配**——只认预定义的有区分度的词：

```python
TERMS = {
    "Claude Code": ["claude code", "claudecode"],
    "MCP": ["mcp"],
    "RAG": ["rag"],
    "向量数据库": ["向量数据库", "向量库", "milvus"],
    "装修避坑": ["装修避坑"],
    ...
}
```

再加泛词过滤：

```python
GENERIC = {"ai", "人工智能", "干货", "教程", "推荐", "分享", "抖音",
           "大模型", "工具", "神器", ...}
```

「AI」这种词 600 条里出现 550 次，没有任何检索价值，必须滤掉。

### 6.6 第三个维度：内容形态

同样是找 Codex 资料，需求可能完全不同：想快速上手 vs 想避雷。

```python
FORMS = [
    ("保姆级教程", [r"保姆级", r"手把手", r"喂饭", r"从零", r"零基础"]),
    ("实战案例", [r"实战", r"案例", r"复刻", r"我用[^\s]{0,6}做", r"实测"]),
    ("工具推荐", [r"推荐", r"神器", r"第\s*\d+\s*个工具", r"安利"]),
    ("原理讲解", [r"原理", r"讲透", r"详解", r"为什么", r"底层", r"机制"]),
    ("避坑经验", [r"避坑", r"别买", r"教训", r"后悔", r"智商税", r"翻车"]),
    ("资源合集", [r"合集", r"大全", r"整理了", r"路线图", r"\d{2,}个"]),
]
```

于是形成三个正交维度：**需求分类**（找什么领域）× **内容形态**（要什么类型）× **术语**（精确定位）。

## 七、第五步：输出

### 7.1 单文件 HTML

数据直接内联进 HTML：

```python
html_doc = TEMPLATE.replace("__DATA__", json.dumps(items, ensure_ascii=False))
```

双击就能用，不需要起服务器，也不受浏览器 `file://` 跨域限制。

### 7.2 拆成两个文件

- **收藏文案.html**（10.6MB）— 完整文案 + 时间轴，用于精读
- **收藏脑图.html**（0.5MB）— 只存 180 字摘要，用于导航

一开始把全文塞进脑图，文件 11MB、加载卡顿。摘要足够判断「是不是我要的」，要读全文再去文案库。

### 7.3 搜索实现

700 条规模用不着索引库，前端遍历 + `includes()` 足够（<10ms）：

```javascript
list = list.filter(o =>
  (o.it.t + ' ' + (o.it.k||[]).join(' ') + ' ' + (o.it.x||''))
    .toLowerCase().includes(ql));
```

配合 180ms 防抖和命中高亮即可。

## 八、工程化：两个入口

拆成两个命令，因为两步的时间尺度差了两个数量级：

**`1-抓取收藏.command`** — 几分钟，需要人工介入（登录、进收藏页）

**`2-转写出稿.command`** — 十几小时，全自动

第二步的关键是**真正脱离终端**：

```bash
# 防重复启动
if pgrep -f "run_step2.sh" > /dev/null 2>&1; then
  echo "⚠️  已经有一个转写任务在后台跑了"
  exit 0
fi

: > "$LOG"
MAXMIN=$MAXMIN nohup ./run_step2.sh >> "$LOG" 2>&1 &
disown                    # 关键：脱离 shell 作业控制

sleep 3
tail -f "$LOG"            # 前台只是「看」，关窗口不影响后台
```

`nohup` + `disown` + 独立脚本文件，三者缺一不可。只用 `&` 的话，关闭终端会连带杀掉进程。

3. **同步到飞书/Notion** — 多维表格更适合筛选和移动端查看

## 十、总结：几个通用经验

1. **风控强的站点，用真实浏览器监听 XHR**，比逆向签名划算得多
2. **别信第三方库的错误信息**，直接问数据源要真相
3. **预检查比事后重试便宜** — 一次接口调用省下一小时下载
4. **规则引擎在小数据集上完胜 LLM** — 可解释、可调、零成本
5. **分类维度取决于使用场景** — 按话题分是资料馆思维，按需求分才是工具箱思维
6. **中英文混合文本，匹配逻辑要分流** — `\b` 对中文无效

代码全在仓库里，欢迎按自己的需求改 `taxonomy.py`——那是最值得定制的部分。
